## 4. 五角色推理流程 <!-- consumers: TP07 -->（与 04 §3 流程对应）

| Agent | 推理输入 | 知识依赖 | 产出 |
|-------|---------|---------|------|
| Code Analyst | CPG/AST | — | 代码结构报告（关键路径/入口点/信任边界） |
| Vuln Detector | 结构报告+代码 | L1 Skills；CPG污点追踪；沙箱DSH语义分析 | 候选漏洞（含 EvidenceChain 5步：源识别→污点传播→汇识别→符号验证→知识推理） |
| Severity Assessor | 候选漏洞 | Skills（CVSS/攻击面类知识） | 严重性评估 |
| Fix Advisor | 确认漏洞 | fix-patterns Skills | FixSuggestion（代码补丁+diff） |
| Quality Validator | 全部产出 | false-positive-patterns Skills | 交叉验证结论（元审计闭环） |

> **2026-09-01 修订（人类批准，ADR-175/177 补遗）**：Vuln Detector 行原"ai-inference.Chat"清除——LLM 语义分析走沙箱内 headless DSH（ADR-140/173），不可用降级 dsh-runtime 进程内 RuleScan 并显式标注（ADR-175）。

**GNN 决策（ADR-001）**：图结构分析能力由 CPG 污点追踪（符号方法）+ LLM 语义理解（神经方法）承担，补偿方案为 CPG 污点验证 + 规则引擎兜底，即本节实现。

## 5. 误报反馈闭环 <!-- consumers: TP08,TP10 -->（申报创新点8 改述落地）

```
用户标记误报(SubmitFindingFeedback.FEEDBACK_FALSE_POSITIVE)
  → 落库 + Kafka finding.verdict.updated
  →（KG 增量步已随 ADR-197 删除）聚合≥3次
  → 聚合≥3次 → 固化 false-positive-patterns Skill 条目 → ReloadSkill 生效
  → 下次扫描: Vuln Detector/Quality Validator 命中该模式 → 降置信/预过滤
效果度量: 误报反馈处理后同类误报重复出现率（目标 <20%，M12 验证）
```
