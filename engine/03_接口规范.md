## 1. 接口清单 <!-- consumers: TP03,TP04,TP05,TP06,TP07,TP08,TP09,TP10 -->（按部署服务组织，结构见 proto）

### 1.1 gateway-service（客户端入口）

| 能力 | 说明 |
|------|------|
| 路由 | REST `/v1/*` → 内部 gRPC 映射；gRPC 直通 |
| 认证 | JWT（access 30min / refresh 7d），校验转发至 UserService.ValidatePermission |
| 限流 | 单用户 50 req/min（见 07 §7） |
| 暴露接口 | 登录/刷新/项目CRUD/任务CRUD/报告查询/结果查询（网关只做转发，不定义新接口） |

### 1.2 project-service（ProjectService + UserService）

ProjectService：CreateProject / GetProject / UpdateProject / DeleteProject / ListProjects / GetProjectConfig / UpdateProjectConfig / GetProjectStats / AddProjectMember / RemoveProjectMember / ListProjectMembers。

UserService：Login / Logout / RefreshToken / GetCurrentUser / GetUser / UpdateUser / ValidatePermission / GetUserPermissions。**V1.0 无 MFA**。

### 1.3 task-service（TaskService，17 RPC）

- 生命周期：CreateScanTask（幂等）、GetScanTask、CancelScanTask、RetryScanTask、ListScanTasks；
- 审批：SubmitTask（CREATED→PENDING）、ApproveTask、RejectTask；
- 状态机：StartTask、CompleteTask、FailTask、UpdateStageStatus；
- 回调（幂等，供内部服务）：ReportStageComplete、ReportStageFailed；
- 进度：GetTaskProgress、WatchTaskProgress（服务端流）、GetTaskContext。

### 1.4 result-service（ResultService + ReportService）

ResultService：finding CRUD + BatchCreate/BatchUpdate（幂等）+ BatchUpdateVerdict + UpdateVerdict + GetFindingsByVerdict + GetTaskResultStats + ExportFindings + **SubmitFindingFeedback**（误报反馈闭环入口）。

ReportService：GenerateReport（幂等；**仅作 Kafka 不可用时的降级路径**，ADR-006）、GetReport、ListReports、ListTemplates、GetTemplate、DownloadReport（流式）。

### 1.5 dsh-runtime-service（DSHRuntimeService 11 RPC + CodeAnalysisService 5 RPC）

**DSHRuntimeService（11 个）**：

| RPC | 用途 | 幂等 |
|-----|------|------|
| RunAIAnalysis | 模式B/C 主分析（**必须携带幂等键**；ADR-186 五模式矩阵） | ✅ |
| VerifySASTResults | 模式D AI增强SAST 阶段3：SAST逐条沙箱验证（**必须携带幂等键**；ADR-186 复用原4a，含同文件同段去重——一组一轮沙箱，判定广播） | ✅ |
| SearchMissedVulns | 【已弃用 ADR-182】原4b 漏报搜索（能力保留，无新模式调用） | ✅ |
| ReviewSASTResults | 【已弃用 ADR-182】旧模式D AI审核（能力保留，无新模式调用） | ✅ |
| ListSkills / GetSkillInfo / ReloadSkill | Skills 管理与热加载 | ReloadSkill 管理操作 |
| GetAnalysisProgress / WatchAnalysisProgress | 进度查询/流 | 只读 |
| GetSessionStatus / CancelAnalysis | 会话管理 | 只读/幂等 |

CodeAnalysisService：AnalyzeCode（幂等；`changed_files` 为空=全量、非空=增量）、QueryCPG、GetCallGraph、GetDataFlow、GetAnalysisProgress。**ExtractFeatures 已删除**（ADR-001）。

### 1.6 ai-inference-service（已删除，编号保留不复用）

> **2026-09-01 修订（人类批准，ADR-175/177）**：ai-inference-service 与 AIInferenceService 契约（7 RPC：Chat/ChatStream/ListModels/GetModelInfo/HealthCheck/RuleScan/ListRules）整体移除（九服务→八）——LLM 语义分析走沙箱内 headless DSH（ADR-140/173），RuleScan 规则兜底内嵌 dsh-runtime 进程并显式标注降级（ADR-175）。原"显式链路约定（dsh-runtime 全部 LLM 调用经 Chat/ChatStream）"随之作废；后续节号不变。

### 1.7 knowledge-service（KnowledgeGraphService 8 RPC + RAGRetrievalService 6 RPC）

> **2026-09-04 修订（人类批准，ADR-197）**：knowledge-service 与上述两契约（14 RPC）整体移除（八服务→七）——知识双层仅保留 L1 Skills（随 DSHRuntimeService），Neo4j/Milvus 出栈，KG 增量消费链（finding.verdict.updated→UpdateCodeKG）随之作废。本节保留作历史契约记录，节号不复用。

KnowledgeGraphService：QueryCWE / QueryAttackPattern / QueryDefenseStrategy / QueryCodeEntities / QuerySemanticSimilar / CrossLayerReasoning / UpdateCodeKG（事件驱动增量更新，消费 `finding.verdict.updated`）/ **GetKGQuality**（KG 质量评估，V2.0 新增）。

RAGRetrievalService：Retrieve / RetrieveWithContext / IndexDocument / UpdateDocument / DeleteDocument / GetIndexStats。**RebuildIndex 不作同步 API**（后台任务，运维触发）。

### 1.8 sast-adapter-service（SASTAdapterService 6 RPC + SASTFusionService 9 RPC）

SASTAdapterService：RunSASTScan（**必须携带幂等键**）、RunMultipleScans、ListAvailableTools、GetToolInfo、ValidateToolConfig、GetScanProgress。

SASTFusionService：FuseResults（幂等）、AlignLocations、ClusterFindings、ResolveConflicts、GetFusionConfig、UpdateFusionConfig + **并入的对比三接口** CompareResults / CalculateMetrics / GenerateComparisonReport（模式E 对比，ADR-186 前称"模式D"；SASTComparisonService 已删除，ADR-005）。

### 1.9 storage-service（StorageService 6 RPC + NotificationService 4 RPC，V2.0 新增定义）

StorageService：UploadFile（客户端流）/ DownloadFile（服务端流）/ GetPresignedUrl（前端直传）/ GetFileInfo / DeleteFile / ListFiles。

NotificationService：SendNotification / SendBatchNotification / ListNotifications / MarkNotificationRead。消费 Kafka 五事件并投递（邮件/Webhook/站内）。

## 2. 幂等规范 <!-- consumers: TP03,TP04,TP05,TP08 -->

| 规则 | 内容 |
|------|------|
| 幂等键 | `RequestMetadata(caller_service, request_id)`，UUID v4 |
| 去重窗口 | 24h（Redis 记录已见键） |
| 冲突响应 | 键重复但请求体 hash 不同 → `ALREADY_EXISTS(9)`；相同 → 返回首次结果 |
| 强制携带 | RunAIAnalysis / ReviewSASTResults / RunSASTScan / AnalyzeCode / FuseResults / GenerateReport / Batch* 写接口 |
| 违例 | 未携带幂等键的写请求 → `INVALID_ARGUMENT(3)` 拒绝 |

## 3. 错误码规范 <!-- consumers: TP03,TP04,TP05,TP06,TP07,TP08,TP09,TP10 -->

采用 gRPC 标准码 + 领域扩展：

| 场景 | 码 |
|------|----|
| 参数缺失/幂等键缺失 | INVALID_ARGUMENT(3) |
| 重复创建（幂等冲突） | ALREADY_EXISTS(9) |
| 任务状态不允许该操作 | FAILED_PRECONDITION(9) |
| 资源不存在 | NOT_FOUND(5) |
| 配额超限（并发/限流） | RESOURCE_EXHAUSTED(8) |
| 下游超时 | DEADLINE_EXCEEDED(4)（任务级转 TaskStatus.TIMEOUT） |
| 内部错误 | INTERNAL(13)，必须带 request_id 便于追踪 |

错误体结构见 proto `ErrorResponse`（含 request_id/trace 链路字段）。

## 4. 鉴权规范

- JWT：access_token 30min，refresh_token 7 天，网关校验、服务间 mTLS；
- 权限模型：资源类型 project/task/finding × 操作 read/write/delete/admin；
- 服务间调用：内部 ServiceAccount，不走用户 JWT；
- **V2.1（ADR-205，2026-09-05 人类指令）**：
  - access claims 增 `role`（proto `Role` 枚举字符串，签发自 project-service 用户记录）；旧令牌无 role claim，管理路由一律 403，重新登录即获得；
  - 管理端门禁（GET/POST /v1/users、POST /v1/users/{id}/password:reset）在网关按 `role==ROLE_ADMIN` 强制；服务端侧强制（gRPC metadata 贯通 caller 身份）为 V2.2 候选；
  - 注册策略：`auth.registration_mode = invitation | open | disabled`（缺省 invitation，configs 全局配置）；注册即登录（RegisterUser 返回令牌对）；
  - 密码：bcrypt 存储，永不明文落库/落日志；自助改密 `POST /v1/users/me/password`（user_id 由网关从 JWT 注入，self 语义）；`must_change_password` 置真期间前端强制改密，ChangePassword 成功即清除；
  - 幂等：RegisterUser/CreateUser/ChangePassword/ResetPassword 携带 `RequestMetadata`，同键同体重放首次响应、同键异体 ALREADY_EXISTS（契约 test_user_lifecycle_contract.py 锁定）。

## 5. 分页/排序/过滤规范 <!-- consumers: TP04,TP08 -->

统一 cursor-based（结构见 proto `PaginationRequest/Response`）：默认 page_size=20，最大 100。**禁止 offset 分页**。

## 6. 版本与兼容策略 <!-- consumers: TP02,TP03 -->

- proto 包名带 `.v1`；破坏性变更升 `.v2` 并保留 `.v1` 双活 ≥2 个发布周期；
- 字段只增不改号；枚举只追加不删改；
- 契约测试以 proto 为准自动生成（见 10 测试计划），CI 拦截不兼容变更。

## 7. 数据流转总览（路径定义见 04，此处只列通道）

| 通道 | 用途 |
|------|------|
| gRPC 同步 | 全部服务间请求/响应（超时矩阵见 07 §8） |
| Kafka `task.completed` | 触发报告生成（主路径，ADR-006）与完成通知 |
| Kafka 其余4 topic | 通知触发（↪KG 增量更新消费已随 ADR-197 删除） |
| MinIO | CPG、报告文件、SAST 原始输出；经 StorageService.GetPresignedUrl 直传 |
