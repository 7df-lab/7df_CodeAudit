## 1. 系统概述

CodeAudit 是与传统开源 SAST 工具深度协同的智能代码安全审计系统：以 DSH Agent 编排五角色多智能体，以 MiMo-v2.5-pro 为默认 LLM（备选 DeepSeek-Coder-V2 / Qwen2.5-Coder），支持五种扫描模式，输出统一审计结果（UnifiedFinding）与审计/对比/审核三类报告。

## 2. 八层逻辑架构 <!-- consumers: TP02,TP07,TP09,TP10 -->

```
┌─────────────────────────────────────────────────────┐
│ 1 展现层  Web控制台 / IDE插件(VS Code, IntelliJ) / CLI / Webhook │
│ 2 编排层  task-service（状态机+Saga）/ gateway / 通知触发        │
│ 3 推理层  dsh-runtime（五角色Agent编排+内置RuleScan兜底，ADR-175/197）     │
│ 4 融合层  sast-adapter 内融合模块（对齐→聚类→冲突消解→AI验证→输出+对比）│
│ 5 引擎层  CPG构建(Joern) / AST解析(Tree-sitter) / 污点追踪 / RAG检索 │
│ 6 适配层  10个SAST适配器（统一解析为UnifiedFinding）              │
│ 8 数据层  PostgreSQL / Redis / MinIO / Kafka（ADR-197 后无 Neo4j/Milvus）│
└─────────────────────────────────────────────────────┘
```

| 模式 | scan_mode 枚举（proto V2.0） | 流程概述 | 适用场景 |
|------|------------------------------|---------|---------|

## 4. 七服务架构 <!-- consumers: TP02,TP04,TP05,TP06,TP07,TP08,TP09,TP10 -->

> **2026-09-01 修订（人类批准，实现事实源 ADR-175/177）**：ai-inference-service 整体移除，九服务→八——LLM 语义分析由沙箱内 headless DSH 承担（ADR-140/173），RuleScan 规则兜底内嵌 dsh-runtime 进程并显式标注降级（ADR-175）。
>
> **2026-09-04 修订（人类裁决，ADR-197）**：knowledge-service 整体移除，八服务→七——Neo4j/Milvus 后端从未实接（KG 恒 NOT_AVAILABLE、RAG 为哈希伪嵌入，ADR-135），Skills 管理随服务删除；proto 契约同步手术（11 logical service）。

### 4.1 部署服务清单

| # | 服务 | 职责 | 技术栈 | 参考资源 |
|---|------|------|--------|---------|
| 1 | gateway-service | API网关、JWT认证、路由、限流 | Go | 2C4G×2 |
| 2 | project-service | 项目管理+用户管理（含UserService） | Go+PostgreSQL+Redis | 2C4G×2 |
| 3 | task-service | 任务编排、状态机、Saga补偿 | Go+PostgreSQL | 2C4G×2 |
| 4 | result-service | 审计结果+报告生成（含ReportService） | Go+PostgreSQL+MinIO | 2C4G×2 |
| 5 | dsh-runtime-service | Agent编排、代码分析（含CodeAnalysisService） | Go+DSH（曾为 Python，已重写） | 8C32G×3（GPU 项待裁决：ADR-175 后推理在沙箱内，引擎侧现栈无 GPU 声明） |
| 6 | sast-adapter-service | 10适配器、融合引擎、对比分析 | Go+Python | 4C16G×2 |
| 7 | storage-service | 文件存储、缓存、消息、通知（含NotificationService） | Go+MinIO+Redis+Kafka | 2C4G×2 |

### 4.3 服务间通信总览（细节见 03/09）

- **同步**：服务间 gRPC（mTLS）；客户端→gateway REST/gRPC；
- **异步**：Kafka topic（`task.created` / `task.stage.completed` / `task.completed` / `finding.created` / `finding.verdict.updated`），生产者 task/result，消费者 notification/report（↪knowledge 消费者已随 ADR-197 删除）；
- **对象存储**：MinIO（报告、CPG、原始SAST输出）。

## 5. 技术栈定版 <!-- consumers: TP02,TP07 -->（唯一来源，禁止重复表）

| 类别 | 选型 |
|------|------|
| LLM | **MiMo-v2.5-pro**（默认，1T参数/1M上下文）；备选 DeepSeek-Coder-V2 / Qwen2.5-Coder（经 OpenShell 网关推理路由，ADR-173/175） |

| 后端 | Go（全部 7 服务；dsh-runtime 已由 Python 重写为 Go） |
| 前端 | React + TypeScript + Monaco Editor |
| 数据层 | PostgreSQL / Redis / MinIO / Kafka |
| 部署 | docker compose（现行，事实源=伞仓 deploy/prod/）；Kubernetes + Helm 为目标形态 |

## 6. 五角色多智能体 <!-- consumers: TP07 -->（定义处；资源配置见 07 §8.1）

| Agent | 职责 | 关键依赖 |
|-------|------|---------|
| Code Analyst | 代码结构分析、依赖追踪 | CPG/AST、read/bash/grep/glob |
| Vuln Detector | 漏洞识别：CPG污点追踪+LLM语义分析+知识双层检索 | Skills→KG→RAG 递进 |
| Severity Assessor | CVSS评分、影响范围 | KG(SecKG) |
| Fix Advisor | 修复方案与补丁 | fix-patterns Skills |
| Quality Validator | 交叉验证、误报过滤（元审计闭环） | 全部前序产出 |
