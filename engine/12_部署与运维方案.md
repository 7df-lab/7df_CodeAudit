## 2. 发布策略 <!-- consumers: TP02 -->

| 服务 | 策略 |
|------|------|
| gateway / project / task / result / storage | 滚动更新（maxUnavailable=0） |
| dsh-runtime / sast-adapter | 蓝绿（推理服务需会话排空，drain 30min；↪knowledge 已随 ADR-197 删除） |

发布前置检查：契约测试通过（proto 兼容性）、镜像签名验证、Helm diff 评审。

## 3. 回滚策略 <!-- consumers: TP02,TP03 -->（A8/X7 收敛：三级阈值，数值见 07 §4）

| 级别 | 触发 | 动作 |
|------|------|------|
| L1 自动告警 | error_rate>1% 持续5min 或 同步API P95>500ms 持续5min | 值班确认，准备回滚 |
| L2 自动回滚 | error_rate>5% 或 P99>3×基线 | Helm rollback 至上一版本，冻结发布窗口 |
| L3 应急 | 核心服务不可用>10min | 回滚+切换备用LLM路由（MiMo→DeepSeek）+状态公告 |

回滚后任务处理：RUNNING 任务不中断（旧版本 Pod 排空）；新任务排队至回滚完成；DEAD 任务人工评估。

## 6. 容量规划（基线见 07 §6）

- 起步容量：50 并发任务 / 10-20 并发项目（V1.0 目标）；
- 扩容信号：队列等待 >10min 或 沙箱占用 >80%；
- dsh-runtime HPA：CPU>70% 扩容，上限 6 副本（受 GPU 与会话上限约束）。
