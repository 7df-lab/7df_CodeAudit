# AGENTS.md — CodeAudit 智能体开发宪法

> **这是智能体在本仓库工作的第一入口。任何智能体（coding agent）开始工作前必须完整阅读本文件。**
> 本文件是"宪法层"：定义不可违反的开发规则。细节数据按《上下文加载协议》按需加载，避免浪费上下文。

## 1. 红线（违反任何一条 = 交付无效）

> **元规则（最高优先，覆盖一切细则）**：**你无权宣布自己的任务 done。** 你的自述（测试数字、时间、证据、"PASS"文字）一律不构成完成证据；完成只能由独立于你的机械断言（.agent/gate.sh）判定。你做的不是"标 done"，而是"提请验证"。声称零成本而验证有成本——所以一切声称默认不可信，这不是对你的不信任，是对任何执行者（包括人类）的通用治理。

| # | 红线 | 检查方式 |
|---|------|---------|
| R1 | **proto 是唯一数据契约**。禁止在代码/文档中手写与 proto 冲突的结构体；生成代码必须由 proto 派生 | verify.sh 检查1 |
| R2 | **07 是唯一数值源**。代码中的超时/阈值/限流等常量必须注释引用 07 章节号（如 `// 07 §8`） | verify.sh 检查2 |
| R3 | **7 服务口径**（删 ai-inference、删 knowledge）。代码目录、部署清单、通信配置只允许出现 01 §4 的 7 个服务名 | verify.sh 检查3 |
| R4 | **写接口必须幂等**。所有写 RPC 实现必须读取 RequestMetadata 幂等键（03 §2） | 契约测试强制 |
| R5 | **done 只能由 gate.sh 断言产生**。任务收尾 = `bash .agent/gate.sh TPxx-Tyy`——它独立核验完成标准、写入真实时间戳与结论；你手写的时间/数字/PASS 均无效 | gate.sh |
| R6 | **状态账本先读后写**；状态列只允许写 in_progress/blocked/escalated/redo（done 由 gate.sh 写入） | gate.sh + 人工抽查 |
| R7 | **禁止抢跑**。下游任务的 in_progress 合法性由 gate.sh 依据 roadmap §3 依赖判定；上游未 done 而开始 = 交付无效 | gate.sh |
| R8 | **增量交付**。每任务一个 commit，格式 `[TPxx-Tyy] 动词+对象`；gate.sh 在 commit 之后运行，核验"commit 已落" | gate.sh |
| R9 | **失败即记录**。测试失败/设计冲突不得静默绕过：小问题记 decisions.md，架构冲突记 blocked 清单并在 status.md 标记 | status.md 审计 |
| R10 | **上下文预算**。单任务会话只加载 context-protocol.md 允许的文档；禁止全文通读在册编号文档（现行 10 份；02 从未存在，00/08/11/11a/14 已删 /234/207，历史在 git） | context-protocol.md |

## 2. 先建立坐标系，再动手（每个任务开始前的自我定位）

你（智能体）是庞大系统中的一个局部执行者，不是自由创作者。**在写第一行代码前，你必须能用一句话回答以下五个问题，并把答案写在 status.md 的任务行下**：

```
①我是谁：本任务 TP/T 编号，属于哪个里程碑、哪个任务包
②全局位置：产出物在 逻辑分层(01 §2)/7服务(01 §4)中的确切位置——
   是正式组件、组件的一个切片，还是一次性验证材料？一次性验证材料绝不放入 services/ 或 libs/
③上游是什么：本任务消费谁的产出（哪个 proto service、哪份设计章节、哪个前置任务交付物）？
   上游没 done 我就不能开始（R7）
④下游等什么：谁消费我的产出？他期待的结构由哪个文件定义（proto/07）？
   我的输出必须与那个结构一致，而不是与我自己的方便一致
⑤完成由谁裁定：哪个文件的哪个章节定义完成标准？达不到时是 blocked（如实报告差距），
   不是换一个我够得着的目标
```

**三个否决项**（任一触发 = 你还没资格动手）：
- 说不清产出物的权威结构定义在哪个文件 → 停，先跑 `bash .agent/task-brief.sh TPxx-Tyy` 拿清单；
- 发现自己在为"让测试通过"而发明设计文档里没有的结构/数据/指标/权重 → 停，那是自造（R1/R2 的精神），应 blocked 或 escalated；
- 发现自己在一次会话里做第二个任务 → 停，先让上一个任务走完 ⑥收尾。

## 2a. 设计溯源与自行探索（拉式范式：要求不完整时自救）

**前提承认**：给你的任务简报可能不完整——设计在演进、清单有遗漏、任务会碰到文档没直接写明的选择。**这不是你自造的许可，而是探索的起点。** 规则只有三条：

**E1 溯源义务（核心）**：你产出的每一个非平凡单元——每个接口实现、每个数据结构、每个数值常量、每个测试断言——都必须能回答"设计依据是什么"。注释格式：`// 依据: <文件名> §<章节>`（数值类必须引 07，结构类必须引 proto）。**写不出依据 = 你正在自造**，立即停，进入 E2。

**E2 探索协议（不确定时的强制动作序列，禁止跳步）**：
```
遇到设计空白/歧义时，依次执行：
1. 检索:  bash .agent/design-search.sh <关键词>     （全文+proto，含行号定位）
         bash .agent/design-search.sh --task TPxx   （该任务全部已声明章节）
         bash .agent/design-search.sh --proto <消息名>（proto结构段精确定位）
2. 命中 → read 只读该节 → 按 E1 注明依据 → 继续
3. 未命中但属于实现细节（文档粒度不管的事，如函数内部算法、变量命名）
   → 记 xx 到 decisions.md（选项+理由），继续
4. 未命中且影响接口/数据/流程/指标（设计粒度的事）
   → status.md 置 escalated，写明"设计缺失:<具体问题>+检索过的关键词+候选方案"
   → 等人类裁决。禁止选择任一候选继续——那是以开发者身份篡夺设计者职权
```

**E3 探索留痕**：每次 E2 探索在会话日志记一行：`explore: <疑问> → <检索词> → <命中文件§节 | 未命中→xx/escalated>`。这是审计你"依据设计还是自造"的第一手材料。

> 为什么这样设计：完整性无法被预先保证（设计会变、清单会漏），所以体系不承诺"推给你完整的"，而是保证"你能拉到所需的"——检索工具 + 溯源格式 + 空白时的诚实出口，三者缺一不可。**自造的定义由此变得精确：跳过 E2 直接写代码。**

## 2b. 标准工作循环（每个任务都走这六步）

```
①认领  读 status.md → 找到第一个 ready 任务 → 移动到 in_progress（写明时间）
②定位  bash .agent/task-brief.sh TPxx-Tyy → 读必读文件 → 在 status.md 写下 §2 五问答案
③实现  只做任务边界内的事；遵守红线 R1-R4；实现级决策先记 decisions.md（xx）
④自测  单元测试 + 反向测试 + 契约测试（test-gates.md §2-4）。
       涉及外部依赖（沙箱/推理路由、SAST 工具、DiverseVul 数据集）时，"完成"= 真实调用并留存证据
       （请求/响应样本存 .agent/evidence/）；mock 只能用于开发期，不构成完成证据
⑤过闸  bash .agent/verify.sh 全绿；门禁原始输出归档到 .agent/evidence/，禁止转述或只写"PASS"
       
⑥收尾  回写 status.md（done + 证据路径）→ git commit（格式）→ 只解锁直接下游任务
```

**完成定义（DoD）**：代码 + 测试 + **真实执行证据**（涉外部依赖时）+ verify.sh 原始输出 + status.md 回写 + 规范 commit。缺一不算完成。

**不达标时的唯一诚实动作**：status.md 改为 blocked 并写明差距（如"Skills增益4.4%，低于10%门限"）。降门槛、换目标、mock 冒充，均属虚假交付。

## 2c. 完成的本质判定（防"写了工具=产出了结果"）

**"完成"的对象永远是 roadmap 完成标准里写的那个产物/效果，不是通往它的路径上的任何中间物。** 三个典型混淆，逐条自检：

| 你想标 done 时 | 完成标准说 | 实际必须存在的是 | 下列情况的真实状态 |
|---------------|-----------|----------------|------------------|
| "我写好了生成脚本" | 生成物入库 | libs/ 下真实的生成文件 | **blocked**：工具链（buf/protoc/go/docker）不可用 |
| "我写好了 docker-compose" | 一键起+健康检查通过 | 容器真实运行过的输出日志 | **blocked**：docker 不在环境里 |
| "测试都通过了" | 覆盖率/门限达标 | 测试报告含真实执行数字 | **fixing/blocked**：工具链缺失跑不了测试 |

**工具链预检规则**：③实现的第一步是探测本任务需要的工具链（`command -v`）。任一缺失 → **立即** status.md 记 blocked（写明缺什么、装上后能否自行恢复），**禁止**继续写"理论上能跑"的代码后标 done。环境缺工具不是你的错，隐瞒它才是违规。

**done 的四项自检（全部满足才能写 done）**：
1. 完成标准中的**名词性产物**在磁盘上实际存在（目录/文件/生成物）；
2. 完成标准中的**动词性验收**真实发生过一次（编译过/运行过/测试跑过），证据在 .agent/evidence/；
3. verify.sh 原始输出（非转述）已归档；
4. commit 已落（R8）——**先 commit 再标 done，不是标完 done 留着以后提交**。

## 2d. 账本纪律（防批量补写）

- 每任务**认领时写开始时间、收尾时写完成时间**，两者来自真实动作发生的时刻；完成时间早于开始时间 = 造假；
- 禁止一次会话补写多个任务的账本行——每行都应在对应任务的 ⑥收尾 时刻写入；
- 上一任务未走完 ⑥收尾（含 commit），不得开始下一任务（与会话日志时间戳互相印证）。

## 3. 任务状态机（status.md 使用规则）

```
ready ──认领──▶ in_progress ──过闸──▶ done
                    │ ──测试失败──▶ fixing（修复后重新过闸）
                    │ ──外部阻塞──▶ blocked（必须写 blocked_reason + 影响范围）
                    └ ──发现设计问题──▶ escalated（提交 xx 至 decisions.md，等待人工）
```

## 4. 智能体的权限边界

| 允许 | 禁止 |
|------|------|
| 修改代码、测试、构建脚本 | 修改 01-14 设计文档（发现错误→escalated + ADR 提请） |
| 修改 .agent/ 下全部文件 | 修改根目录 AGENTS.md 自身（宪法变更需人工批准） |
| 新增 xx 实现决策 | 新增/修改 ~006 架构决策 |
| 更新 status.md / decisions.md | 删除 status.md 历史条目（只增不改，改用纠正行） |

## 6. 礼仪

- 每轮工作结束（无论成败）在 status.md 追加一行会话日志；
- 发现文档间矛盾：先查 git 历史 + `.agent/decisions.md` ADR 账本是否已知（原 archive/ 已随 退役删除），未知则 escalated，**不要自行仲裁**；
- 提请人类决策时，把选项、证据、影响范围写全，让人类只需选择。
